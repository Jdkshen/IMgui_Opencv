# Modbus TCP PLC 模拟器

> 文档同步日期：2026-08-02。地址、握手和连续触发规则已与当前主程序及 PLC 回归测试复核，本轮界面整理未改变协议。

该工具用于在没有真实 PLC 时测试视觉主程序的 Trigger、Busy、Done、OK、NG、Error、Heartbeat 和 ACK 握手，以及“PLC 触发指定任务拍照并只执行该任务”。

模拟器只使用 Python 标准库，不需要安装第三方包。当前开发机已验证 Python 3.14 和 Tkinter 8.6。

## 启动

双击：

```text
tools\plc_simulator\run_plc_simulator.bat
```

也可以从 PowerShell 启动并保留控制台错误信息：

```powershell
python tools\plc_simulator\plc_simulator.py
```

默认监听参数：

| 参数 | 默认值 |
| --- | --- |
| IP | `127.0.0.1` |
| 端口 | `1502` |
| Unit ID | `1` |

使用 1502 是为了避免 Windows 下 502 端口的权限或占用问题。需要让局域网其他电脑连接时，可将监听地址改为 `0.0.0.0`，并在 Windows 防火墙中仅允许可信生产网络访问该端口。

## 与视觉主程序联调

1. 启动模拟器，点击“启动 Server”。
2. 在视觉主程序打开“设备连接 → 检测结果输出”。
3. 选择“Modbus TCP 线圈”。
4. 填写 IP `127.0.0.1`、端口 `1502`、Unit ID `1`。
5. 启用“PLC IO 映射与握手”。
6. 保持标准输出映射：Busy=1、Done=2、OK=3、NG=4、Error=5、Heartbeat=6、ACK=7。
7. 为任务添加 Trigger 输入，并确保模拟器和主程序地址一致：

| 任务 | Trigger 地址 |
| --- | --- |
| 任务01 | 0 |
| 任务02 | 8 |
| 任务03 | 9 |
| 任务04 | 10 |
| 任务05 | 11 |
| 任务06 | 12 |
| 任务07 | 13 |
| 任务08 | 14 |
| 任务09 | 15 |
| 任务10 | 16 |
| 任务11 | 17 |
| 任务12 | 18 |
| 任务13 | 19 |
| 任务14 | 20 |
| 任务15 | 21 |
| 任务16 | 22 |

设备页现在会根据当前任务列表自动补齐缺少的 Trigger。旧配置如果只有任务01，可以点击“补齐任务 Trigger”；需要重新生成完整标准地址时点击“恢复标准映射”。

8. 重新连接结果输出。需要测试相机时连接工业相机；只测试文件夹图片时可以不连接相机。
9. 在模拟器点击某个任务右侧的“触发拍照”。
10. 观察 Busy、Done、OK/NG/Error 和 ACK 的变化，以及主程序结果界面是否只更新对应任务。

Trigger 默认保持 ON 500 ms 后自动恢复 OFF。模拟器默认在检测到 Done 后延迟 300 ms 自动发送 ACK；可以关闭“Done 后自动 ACK”并改用“手动发送 ACK”。

视觉程序只在 Busy=OFF 且上一轮 ACK 已完成时接受新 Trigger。连续点击“触发拍照”不会形成待执行队列，Busy 期间的额外 Trigger 会被忽略；这是为了避免停止点击后仍继续补跑旧请求。

输入来源按主程序实际状态决定：相机在线时抓取新帧；相机未连接时使用目标任务自己的图片文件夹、单图或公共图片。若相机已经在线但本轮抓帧失败，主程序会输出 Error，不会偷偷改用旧图片。文件夹模式每个被接受的 Trigger 只推进一张，被 Busy 忽略的 Trigger 不推进索引。

建议联调时分别验证：任务01、任务02和任务16各一次；关闭自动 ACK 后验证一次手动 ACK；在 Busy 期间快速点击 5 次，确认主程序显示忽略计数且 ACK 后没有继续执行。

## 协议能力

- FC01：读取线圈，支持 1-2000 点。
- FC03：读取保持寄存器，支持 1-125 个。
- FC05：写单个线圈。
- FC06：写单个保持寄存器。
- 校验 MBAP Protocol ID、Length、Unit ID、地址范围和数据值。
- 支持多个 TCP 客户端，默认最多排队 8 个连接。
- FC01/FC03 轮询日志默认关闭，避免主程序高频轮询刷屏。

## 协议自测

```powershell
python tools\plc_simulator\plc_simulator.py --self-test
```

自测会在随机本地端口启动 Server，并验证 FC01、FC03、FC05、FC06、非法功能码和错误 Unit ID 响应。

## 常见问题

- 主程序显示连接失败：确认模拟器已经点击“启动 Server”，IP、端口和 Unit ID 完全一致。
- Trigger 没反应：确认主程序 IO 表中的 Trigger 地址和任务绑定正确，并且 Trigger 已恢复 OFF 后再产生下一次上升沿。
- Trigger 被忽略：检查视觉程序是否仍为 Busy、Done 是否仍在等待 ACK；完成 ACK 后再发送新的上升沿。
- 直接输出 Error：检查任务是否启用、是否存在工具，以及任务文件夹/单图能否读取；相机在线但实际抓帧失败也会输出 Error。
- 没有自动清除结果：确认 ACK 地址一致，或点击模拟器“手动发送 ACK”。
- 端口被占用：把模拟器端口改为 1503，并同步修改主程序连接端口。
