# 生产稳定性测试方案

> 文档同步日期：2026-08-26。已完成 1 分钟快速浸泡（9 轮、0 失败）并生成 `samples.csv`/`summary.json`；它不替代 8 小时发布门槛。发布前另需完成 `UI_SMOKE_CHECKLIST.md` 中的启动诊断、独立流程图、字体、工具图标、16 槽相机和高 DPI 检查。

## 自动回归浸泡

运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/run_stability.ps1 `
  -Configuration Release -DurationMinutes 480
```

脚本连续执行完整回归，逐轮采集退出码、耗时、峰值工作集和峰值线程数，
并输出 `samples.csv` 与 `summary.json`。任一轮失败会立即停止并保留该轮标准输出和错误日志。

验收门槛：

- 8 小时零失败；正式交付候选建议延长到 24 小时。
- P99 单轮耗时不超过首 10 轮中位数的 1.5 倍。
- 后 20% 轮次的峰值工作集趋势相对前 20% 不持续增长超过 10%。
- 峰值线程数不随轮次单调增长。

## 产线场景浸泡

自动回归通过后，在真实或等效硬件上执行：

1. 配置 16 个任务，文件夹图片循环至少 50,000 次。
2. PLC 模拟器以生产节拍的 2 倍发送 Trigger，并注入重复 Trigger、延迟 ACK、丢失 ACK 和断线重连。
3. 相机每小时执行一次断线/重连；记录硬件帧号、丢帧数和时间戳连续性。
4. 每分钟采集进程 CPU、工作集、专用字节、GPU 专用内存、句柄数和线程数。
5. 保存平均、P95、P99 检测节拍以及最长连续运行时间。
6. 在 Busy、等待 ACK、算法执行中分别执行一次正常关闭，确认日志与配置文件完整。

发布门槛：无崩溃、无死锁、无配置损坏、无未解释的丢帧；资源曲线稳定，
P99 满足现场节拍预算。浸泡通过不能替代 UI/资源验收；候选包还必须在脱离源码目录后确认字体和 `assets/icons/` 可用。
