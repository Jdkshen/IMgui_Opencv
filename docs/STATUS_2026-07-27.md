## 本轮完成内容

### PLC 连接与 IO 映射

- 沿用设备页中的 PLC IP、端口、Unit ID 和通讯超时参数。
- IO 映射支持信号名、零基协议地址、读写方向、反相、输出脉冲时间和启用状态。
- Trigger 输入额外绑定任务名称；可以配置多行 Trigger，用不同地址分别触发不同任务。
- 当前任务列表会自动补齐缺少的 Trigger；任务01默认地址0，任务02～任务16默认地址8～22。
- “补齐任务 Trigger”保留已有自定义地址并只添加缺项；“恢复标准映射”按当前任务顺序重建16任务地址表。
- 标准信号包括 Trigger、Busy、Done、OK、NG、Error、Heartbeat 和 ACK。
- 启用工业握手后停用旧的单线圈自动发布，避免两个发布路径写入冲突。

默认映射如下：

| 协议地址 | 信号 | 方向 | 默认行为 |
| --- | --- | --- | --- |
| 0 | Trigger | PLC → 视觉 | 上升沿触发任务01 |
| 1 | Busy | 视觉 → PLC | 检测期间为 ON |
| 2 | Done | 视觉 → PLC | 完成后产生 200 ms 脉冲 |
| 3 | OK | 视觉 → PLC | 合格结果 |
| 4 | NG | 视觉 → PLC | 不合格结果 |
| 5 | Error | 视觉 → PLC | 相机、任务、算法或超时错误 |
| 6 | Heartbeat | 视觉 → PLC | 周期翻转 |
| 7 | ACK | PLC → 视觉 | PLC 确认读取结果 |

配置连接前会校验地址是否重复、信号方向是否合法、Trigger 是否绑定有效任务，以及是否至少存在 Trigger、Busy、Done 和一种结果输出。

### 指定任务拍照与执行

PLC 触发采用以下执行链：

```text
Trigger 上升沿
  -> Busy ON
  -> 在线相机抓新帧；无相机则解析任务文件夹/单图/公共图片
  -> 只运行 Trigger 绑定任务中的工具
  -> Busy OFF
  -> Done + OK/NG/Error
  -> 等待 ACK
  -> 清除结果输出
```

- PLC Trigger 会强制抓取新帧，不依赖任务是否勾选“使用工业相机（优先）”。
- 相机在线且抓帧成功后仅执行绑定任务，其他任务和未分组工具不参与本轮检测。
- 相机未连接时自动使用该任务的文件夹或单图，文件夹每次 PLC Trigger 推进一张。
- 相机已经在线但本轮抓帧失败时发布 Error，避免掩盖生产设备故障。
- Trigger 和 ACK 都按 OFF→ON 上升沿识别；PLC 每轮结束后必须把对应输入恢复为 OFF。
- Trigger 不积压：任务已请求、Busy 执行或等待 ACK 时的新上升沿直接忽略并计数，ACK 后不会补跑旧请求。
- 没有启用 ACK 映射时，完成输出发布后直接结束握手。

### 在线诊断与容错

- 界面显示在线状态、最后成功通讯时间、连续失败次数、重连次数和当前退避时间。
- 连续通讯失败达到阈值后按初始时间到最大时间执行指数退避自动重连。
- 检测超时和 ACK 超时分别产生明确的握手报警，不会被后续成功轮询误清除。
- 连续输入地址通过 Modbus 功能码 01 批量读取，减少多点轮询报文数量。
- 支持输入读取、输出 ON/OFF 单点测试。
- 支持 Pass、Fail、Error 整套握手测试。
- 支持在无 PLC Trigger 的情况下模拟“拍照并执行指定任务”。

### 独立 PLC 模拟应用

- 新增基于 Python 标准库和 Tkinter 的图形化 Modbus TCP Server，不需要第三方 Python 包。
- 默认监听 `127.0.0.1:1502`，Unit ID 为 `1`，避免本地 502 端口权限和占用问题。
- 提供任务01～任务16的独立 Trigger 按钮，默认地址与主程序示例映射一致。
- 实时显示 Busy、Done、OK、NG、Error、Heartbeat 和 ACK 线圈状态。
- 支持 Trigger 脉冲、手动 ACK、Done 后延迟自动 ACK、全部线圈复位和通讯日志。
- Server 支持 FC01、FC03、FC05、FC06，以及 MBAP、Unit ID、地址和数据值校验。
- 可通过 `python tools\plc_simulator\plc_simulator.py --self-test` 运行无界面协议自测。
