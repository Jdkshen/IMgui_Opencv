## 本轮整合

### PLC 请求单槽

- `HardwareRuntimeService` 的待执行请求由容器收敛为一个可选槽位，运行时不会积压 PLC Trigger。
- PLC Trigger、界面“模拟触发”和整套握手测试共享同一占用规则。
- 待调度、Busy、等待 ACK 或握手测试期间的新请求直接拒绝，并计入忙碌触发统计；请求释放后也不会补跑。
- 任务请求先完成存在性和启用状态校验，再改变相机抓帧状态，避免无效任务留下残余请求。

### 握手与输出

- ACK 超时保留明确报警，并自动清除 Busy、Done、OK、NG 和 Error 输出。
- 连接、断开和重配统一复位握手状态，降低旧状态跨连接残留的可能。
- `WaitForOutputIdle()` 现在同时等待普通输出、IO 写入、输出脉冲和 worker 空闲，避免 PLC 写入尚未完成时提前返回。
- 输出绑定、适配器键和自动发布状态在对应同步区内更新和读取。

### Trigger 映射同步

- Trigger 使用稳定任务 ID 跟踪任务身份。
- 任务重命名时只更新绑定名称，保留原自定义地址。
- 删除任务时移除对应旧 Trigger；新增任务自动补齐标准 Trigger。
- 任务排序不会改写已有地址；重复同步不会产生重复映射。
- 只有用户选择“恢复标准映射”时，才按当前任务顺序重建标准地址表。

## 回归覆盖

本轮新增或强化的检查包括：

- 第一个待执行任务被接受，第二个并发请求被拒绝并增加忽略计数；
- 存在待执行任务时，整套握手测试不会抢占请求槽；
- ACK 超时后握手结束且所有结果输出恢复 OFF；
- 任务重命名保留自定义 Trigger 地址；
- 删除任务清理旧 Trigger，新增任务获得标准地址；
- Trigger 映射重复同步保持幂等。
