# Development Status: 2026-07-19

## Completed in this work period

- Restored the main Release x64 build after the `small` Windows macro collision in `UI/ToolsWindow.cpp`.
- Ran the complete regression executable after the build, not only policy or caliper subsets.
- Moved real-time YOLO overlay objects, visibility, horizontal offset, and timing statistics into `Core/RealtimeDetectionState`.
- Moved the shared `DetectedObject` data structure into `Core/DetectionTypes.h`.
- Removed the old YOLO overlay globals from the algorithm/UI execution chain.
- Removed algorithm logging dependencies on the UI-wide `ImVec4 color` global.
- Moved multi-color finder runtime count/timing into `ToolChainState` and preview upload into `ImageState`.
- Removed threshold tool image/result/timing globals; the legacy threshold window now reads and writes through `ImageState` and an encapsulated timing accessor.
- Added a Windows GitHub Actions workflow that builds both projects and runs the full regression suite.
- Added `scripts/package_runtime.ps1` and `docs/RELEASE.md` for repeatable runtime ZIP packaging.
- Hardened runtime packaging so missing required DLLs fail the build and the generated
  archive is checked for the executable plus DirectML, NCNN, ONNX Runtime, and OpenCV
  runtime entries before it is accepted.
- Completed the first threshold-state migration: threshold UI parameters now live on
  `ToolInstance`, execution receives an explicit `PipelineState`, and the obsolete
  threshold image/timing globals were removed from source and regression stubs.
- Moved tool move/remove behavior from `UI/ToolsWindow.h` into `Core/ToolChainState`,
  including dependency, active-tool, and real-time-tool index remapping.
- Stopped `RecipeManager::Capture()` from mirroring current threshold/template-match
  tool parameters into deprecated top-level recipe DTO fields.
- Added `docs/DEVELOPMENT_PLAN_2026-07-19.md` as the P0-P4 acceptance checklist.
- Removed the `UI::g_ToolInstances` export from `ToolsWindow.h`; the tool window
  now obtains Core-owned instances only within its rendering function.
- Replaced the tool window's ROI compatibility accesses with `ROIState` and
  `ROIEditorState` APIs, including runtime IDs and selected ROI updates.
- Added Blob aggregate quality measurements for candidate/valid counts, mean area,
  circularity, aspect ratio, and orientation.
- Added reusable named-measurement range judgement. Blob and other tools can apply
  recipe-persisted lower/upper limits to any `ToolResult.measurements` item.
- Added `Core/ImageImportService` so ImageViewer only supplies dialog paths and
  renders diagnostics. Single-image import, recursive folder import, navigation,
  stale-result cleanup, empty folders, missing paths, and async decode failures
  are regression-tested.
- Completed the multi-point calibration editor with table-based sample entry,
  per-sample residuals, model fitting, and backward-compatible JSON import/export.
- Added `Core/InspectionHistory` and connected it to the unified result publication
  path. It records measurement history, computes mean/standard deviation/Cp/Cpk,
  excludes Error samples from statistics, and exports escaped CSV data.
- Extended result ROI selection with category/classId filters, minimum score and
  area filters, and stable source/score/area sorting; Nth selection is applied
  after filtering and sorting.
- Added a shared result-ROI configuration panel: Nth mode shows the selected
  result index, while Nth/all-results modes share category, class ID, score,
  area, sorting, and missing-result policy controls.
- Added a UI run-preflight panel backed by `ToolChainPreflight`; missing image,
  ROI, template/reference asset, OCR/YOLO model, and dependency-cycle issues are
  listed together before execution.
- Added the `ToolInstance.skipIfModelMissing` policy for OCR/YOLO. When enabled,
  missing model errors are published as explicit `Pass + skipped` results and
  do not block the rest of the recipe; image, ROI, template, and dependency
  errors remain blocking preflight issues.
- Moved image zoom, pan, canvas position, and pixel/coordinate grid settings into
  Core `ImageViewState`; ImageViewer and ROIManager no longer export view globals.
- Added persistent tool `groupName`/`collapsed` fields and Core batch enable APIs;
  the tool window now provides group assignment, card collapse, and batch enable/
  disable commands.
- Completed SPC query/presentation flow: Core exposes measurement names and bounded
  trends, while the statistics window provides measurement selection, tolerances,
  mean/standard deviation/Cp/Cpk, recent trends, CSV export, and history clearing.
- Completed Fixture visualization of both reference and current coordinate frames.
- Completed result ROI category/class/score/area filters and deterministic sorting.
- Added Core `ToolAssetService` for template-match, shape-template, multi-color
  reference, and difference-reference capture. Capture sessions use stable `toolId`
  and ROI runtime IDs, so tool moves and ROI index changes do not redirect a capture.
- Removed the exported `UI::gROIs` and `UI::gSelectedROI` compatibility references;
  ROIManager, Sidebar, and regressions now access Core `ROIState` directly.
- Added Core dependency descriptions shared with validation. Tool cards display
  incoming Result ROI/Fixture dependencies, downstream consumers, and invalid links.
- Rebuilt and smoke-tested `dist/IMgui_Opencv-Release-x64.zip`; all required runtime
  binaries were present in the generated archive.
- Added Core `ToolROIService` for bound search-ROI editing. Confirm/cancel/clear and
  tool removal are stable across tool moves and unrelated ROI insertions.
- Added group filtering plus batch result-label visibility and stop-on-failure
  operations for all tools or one group.
- Added Core hardware adapter contracts and lifecycle management for industrial
  cameras, PLC tags, Modbus TCP coils/registers, and OPC UA nodes.
- Added `Core/HardwareRuntimeService`: connected camera frames enter the normal camera
  `FrameSourceState`, while inspection status can be published through PLC, Modbus TCP,
  or OPC UA bindings with optional logic inversion. All routes have offline adapter tests.
- Replaced `RecipeToolInstance : ToolInstance` inheritance with a compact composition
  DTO containing ToolInstance JSON plus template/difference/multi-color asset payloads.
- `RecipeManager::Save()` now writes only from the captured `RecipeData` snapshot;
  `Load()` resolves and loads assets, and `Apply()` performs no recipe asset file I/O.
