# 多相机槽位说明

> 文档同步日期：2026-08-26。本文对应当前 16 槽相机运行时、任务绑定、资源调度和独立在线状态；正式运行包只使用 `IMgui_Opencv-Release-x64.zip`。

当前相机运行时按 16 个独立槽位管理。每个槽位包含自己的适配器、采集线程、触发配置、重连计数、最新帧缓存和在线状态；连接或断开一个槽位不会切换或停止其他槽位。

## 资源调度与内存边界

- 槽位按任务绑定按需激活，未参与本轮检测的相机不会被无条件拉入执行链。
- 同一轮最多 4 个任务并行；ONNX YOLO、OpenCV DNN 和 OCR 各自使用独立的运行时锁，同一后端串行、不同后端可以并行。
- 华睿帧由同步 `IMV_GetFrame` 获取，在 SDK 缓冲有效期内复制到应用持有的 `cv::Mat`，随后始终调用 `IMV_ReleaseFrame`；停止、断开和重连会释放队列中的旧帧。
- 待执行任务只保存引用计数图像头，进入最多 4 个活动 worker 后才创建可写隔离副本，避免一次为 16 个任务预分配整图副本。
- 16 槽是容量上限，不代表同时为 16 台相机长期保留多份全分辨率工作图；任务输入和结果图依靠引用计数/写时复制减少重复分配。

## 任务取帧规则

- 任务组绑定 `相机 01` 到 `相机 16` 后，执行时只读取对应槽位的帧。
- “全部执行”涉及多个相机槽时，会向每个在线绑定槽分别请求本轮新帧，等待全部到齐后再按任务绑定分发；单槽等待上限为 3 秒，超时会按槽号记录错误并使用该任务的备用图片，不会拿其他相机或旧缓存冒充本轮帧。
- 相机异步回帧会恢复发起抓帧时的执行范围，避免等待期间被其他入口改写后把“全部执行”缩成“执行当前任务”；日志标题也严格区分这两个入口。
- 每个槽位独立保存“程序启动时自动连接此槽”。连接成功会自动启用该项，主动断开会关闭；下次启动会逐槽恢复连接，不再只恢复当前预览槽。
- 自动连接和批量取帧不会改变用户当前选择的预览槽。例如当前查看相机 01，即使任务还绑定相机 02、03，执行完成后仍保持相机 01。
- 多任务同时执行时，各任务仍使用自己的相机帧，不再共用当前选中的相机图片。
- 未绑定相机的任务继续使用任务图片或公共图片；“执行当前任务”不会强制抓相机帧。
- 混合执行绑定与未绑定任务时，新相机帧只交给对应绑定任务，未绑定任务保留执行前的公共图片，不会被相机发布动作覆盖。
- 已绑定相机的任务在本轮请求不到新帧时会中止并记录槽号，不再静默使用公共图片、其他相机或旧缓存。

## UI 状态

相机连接页面的每个槽位按钮独立显示“在线/断线”。任务的相机绑定下拉框也会显示对应槽位状态；选择某个槽位只改变当前编辑对象，不会断开其他相机。

采集等待和工具执行期间，各相机线程仍持续更新自己的槽位缓存，但不会把后台预览帧写入公共 `ImageState`。这避免执行中的输入版本变化导致“后台结果已丢弃”。日志会按槽输出本轮帧号和 `dropped` 增量；`dropped > 0` 表示相机 SDK/传输层确实报告丢帧，需要继续检查曝光时间、触发频率、网卡带宽和缓冲策略。

## 兼容说明

旧版通过默认相机适配器进行的一次性抓帧仍可用，但不会自动把该适配器伪装成持续运行的任务相机。正式采集应在目标槽位完成连接并启动采集线程。

视频文件和界面“打开摄像头”属于公共预览源，不等同于工业相机槽。公共预览上的单个 YOLO 工具允许在视频换帧期间发布最近完成的异步结果；需要持续逐帧检测时使用 YOLO 工具卡片的“开始实时检测”。

## 验证建议

1. 连接相机 01 和相机 02，分别绑定任务 A、任务 B。
2. 观察两个槽位的帧计数和在线状态是否独立变化。
3. 同时执行任务 A、B，确认结果图分别来自两台相机。
4. 断开相机 01，确认任务 B 仍可继续采集，任务 A 显示相机 01 的断线原因。
5. 新建未绑定任务 C 并加载一张明显不同的公共图片，分别执行 C 和同时执行 A、C，确认 C 两次都使用公共图片。
