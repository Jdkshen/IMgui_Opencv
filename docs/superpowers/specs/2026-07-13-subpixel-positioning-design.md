# 统一亚像素定位设计

## 状态

已确认采用分阶段迁移方案：先统一浮点坐标和坐标变换链路，再逐类增加算法精修，最终删除整数坐标桥接。

## 目标

1. 所有产生空间位置的工具统一使用浮点图像坐标。
2. ROI 裁剪、旋转、缩放、letterbox 和结果恢复过程中不提前取整。
3. 模板、直线、Blob、轮廓和形状匹配在高对比度测试图上达到中位误差小于 0.5 px。
4. YOLO、OCR、二维码等模型或解码工具保留其原始浮点输出，不再由框架额外引入整数误差。
5. UI 绘制、结果 ROI、结果导出和后续工具输入使用同一套精确坐标。

## 范围

需要迁移的空间结果工具：

- 模板匹配
- Blob 分析
- YOLO 和 OpenCV YOLO
- 轮廓分析
- 形状匹配
- 直线检测
- 多点找色
- OCR
- 二维码识别
- 几何绘制

边缘、阈值、形态学和原图工具只输出图像，不产生独立位置结果，因此只需保证它们不破坏后续工具的坐标变换。颜色分析继续输出统计值；使用 ROI 时保留浮点 ROI 信息。

## 非目标

- 本阶段不实现毫米坐标、相机内参标定或机械坐标系转换。
- 不承诺所有 YOLO 模型的检测误差小于 0.5 px；框架只保证不额外丢失精度。
- 不通过放大图片后直接乘回坐标来伪造亚像素精度。
- 不在每个工具中各写一套 ROI 偏移和缩放恢复逻辑。

## 当前问题

当前公共链路存在三处精度损失：

1. `ToolResult` 使用 `cv::Rect`、`cv::Point` 保存区域、检测框、轮廓和线段。
2. `ROI::ToCvRect()` 把浮点 ROI 转成整数矩形后，部分工具继续把该整数结果作为最终位置。
3. `RotatedROI::RestoreResult()` 使用 `cvRound()` 恢复轮廓和线段坐标。

因此算法内部即使得到浮点坐标，进入统一结果、旋转 ROI 或下游结果 ROI 后仍会退回整数。

## 选定方案

采用“统一浮点结果契约 + 公共坐标变换 + 工具局部精修”的方案。

不长期保留两套平行结果。迁移期间允许存在显式整数栅格转换函数，但 `ToolResult` 的最终空间结果只以浮点坐标为事实来源。旧整数结果字段在所有生产者和消费者迁移完成后删除。

## 浮点结果契约

`ToolResult` 的空间字段最终调整为：

```cpp
struct Region {
    std::vector<cv::Point2f> contour;
    cv::Rect2f bbox;
    bool hasCenter = false;
    cv::Point2f center;
    bool hasOrientedBox = false;
    cv::RotatedRect orientedBox;
    float area = 0.0f;
    float score = 0.0f;
    std::string label;
};

struct Detection {
    cv::Rect2f box;
    int classId = -1;
    float score = 0.0f;
    std::string label;
};

struct Line {
    cv::Point2f p1;
    cv::Point2f p2;
    float length = 0.0f;
    float angle = 0.0f;
};

struct TextItem {
    std::string text;
    cv::Rect2f box;
    bool hasQuad = false;
    std::array<cv::Point2f, 4> quad;
    float confidence = 0.0f;
};
```

二维码复用 `TextItem::quad` 保存四角。OCR 同时保留文字四边形和用于列表显示的轴对齐包围框。

## 栅格转换规则

新增 `ResultGeometry` 公共工具，所有浮点到整数转换必须显式选择策略：

- `CoverRect()`：向外取整，用于裁剪，保证不丢边缘像素。
- `NearestRect()`：四舍五入，用于兼容只接受整数框的第三方 API。
- `ClampRect()`：限制到图像边界。
- `BoundingRect()`：由浮点轮廓或四边形计算浮点包围框。

UI 绘制、结果 ROI 和结果导出不得调用整数转换。只有访问 `cv::Mat` 像素、创建子矩阵或调用整数 API 时才允许转换。

## 公共坐标变换

新增 `CoordinateTransform`，内部使用双精度齐次矩阵 `cv::Matx33d`，统一处理：

- ROI 裁剪偏移
- 旋转 ROI 正向和反向映射
- 图像缩放
- YOLO letterbox 的缩放和 padding
- OCR 检测输入缩放
- 多阶段变换组合

公共接口至少包含：

```cpp
cv::Point2f MapPoint(const cv::Point2f& point) const;
cv::Rect2f MapRectBounds(const cv::Rect2f& rect) const;
std::array<cv::Point2f, 4> MapQuad(const std::array<cv::Point2f, 4>& quad) const;
CoordinateTransform Then(const CoordinateTransform& next) const;
```

`RotatedROI`、YOLO、OCR 和二维码不得继续手写偏移量或在中间阶段 `cvRound()`。

## 各工具精修方法

### 模板匹配

1. 保留整数像素上的粗匹配和 NMS。
2. 对每个最终峰值读取响应图的 3x3 邻域。
3. 使用二维抛物面或分离的一维二次插值计算 `dx/dy`，偏移限制在 `[-0.5, 0.5]`。
4. 旋转模式先保持离散角度；后续可对最佳角度两侧分数做角度二次插值。

### Blob 和轮廓

1. 使用 `cv::moments` 的双精度结果计算浮点质心。
2. 轮廓顶点保留为 `Point2f`。
3. 高精度模式在灰度梯度上沿轮廓法线做局部插值，再重新计算中心和包围框。
4. 面积继续以浮点值保存。

### 直线检测

1. Hough 线段只作为粗定位。
2. 收集线段附近窄带内的边缘点。
3. 使用 `cv::fitLine` 最小二乘拟合浮点直线。
4. 用拟合直线与有效边缘范围求浮点端点、长度和角度。

### 形状匹配

1. 保留当前轮廓匹配作为候选生成。
2. 在候选附近建立距离变换或边缘代价图。
3. 对平移位置做小范围局部优化，并用二次插值求浮点最佳位置。
4. 旋转矩形继续使用 `cv::RotatedRect` 保存。

### 多点找色

1. 整数扫描继续用于粗定位。
2. 在最佳点周围使用双线性采样计算颜色误差曲面。
3. 误差曲面稳定时做 3x3 二次精修。
4. 曲面不稳定或图像为严格二值图时保留像素级结果，不输出虚假的小数精度。

### YOLO

1. 检测器内部框使用浮点坐标。
2. 精确反算 resize、letterbox padding 和 ROI 偏移。
3. NMS 使用浮点框。
4. 可选的边缘吸附精修独立开关，默认不改变语义边界模糊的检测框。

框架验收只检查坐标反算误差，不把模型本身的定位误差算作框架误差。

### OCR 和二维码

1. 保留检测器返回的浮点四角。
2. ROI、旋转和缩放恢复直接作用于四角。
3. OCR 的显示矩形由四角计算，不再反过来作为精确结果。
4. OpenCV 二维码角点可选使用 `cornerSubPix` 精修。
5. ZXing 只提供整数角点时标记为像素级，不能仅通过类型转换声称为亚像素结果。

### 几何绘制

几何数据已经以浮点图像坐标编辑。迁移后直接发布 `Point2f/Rect2f/RotatedRect`，不再经过整数 `bbox` 再生成下游 ROI。

## 精度状态

空间结果增加精度状态，至少区分：

- `Pixel`：算法只有像素级结果。
- `Subpixel`：执行了局部亚像素精修。
- `ModelFloat`：模型输出为浮点，但没有经典亚像素精修保证。

UI 和导出报告显示该状态，避免把带小数的坐标误认为已经达到亚像素准确度。

## UI 和工具链

- 图像叠加层直接使用浮点坐标绘制。
- 坐标和尺寸默认显示三位小数。
- “结果 ROI”从浮点框、浮点轮廓或旋转框生成 ROI。
- 下游工具接收浮点 ROI；裁剪时保存整数裁剪框到原图的精确变换。
- 结果 JSON 增加 `coordinateUnit: "pixel"` 和精度状态。
- 配方格式不保存运行时 `ToolResult`，因此旧配方不需要迁移空间结果字段。

## 性能约束

- 坐标变换不得复制整图。
- 经典工具的精修只在候选附近执行，不做第二次全图扫描。
- 单个经典工具的精修附加耗时目标不超过 2 ms。
- 多目标工具限制精修候选数量，使用现有最大结果数作为上限。
- YOLO 边缘精修和形状高精度模式允许作为可选高精度档位。

## 测试策略

### 公共坐标测试

1. 平移、缩放、旋转和组合矩阵往返误差小于 0.05 px。
2. 浮点结果经过旋转 ROI 裁剪和恢复后保持坐标、角度和尺寸。
3. 结果 ROI 传给下游工具后不发生整数截断。
4. UI 标签、JSON 和运行报告保留小数坐标。

### 工具精度测试

使用 `warpAffine` 对基准图施加 0.1 px 步进的已知平移，并加入可控模糊和噪声：

- 模板匹配：比较模板中心误差。
- Blob、轮廓：比较质心和边缘位置误差。
- 直线：比较端点、角度和线到真值的距离。
- 形状匹配：比较候选中心误差。
- 多点找色：比较锚点误差，并验证不稳定曲面回退为像素级。
- OCR、二维码：比较四角恢复链路，不要求识别模型本身达到 0.5 px。
- YOLO：使用固定浮点模拟输出验证 letterbox 和 ROI 反算。

验收同时记录中位误差和 P95，避免少量异常点被平均值掩盖。

## 验收标准

- 公共坐标变换链路误差小于 0.05 px。
- 高对比度经典定位工具的中位误差小于 0.5 px。
- P95 默认目标小于 1.0 px；达不到时必须在工具测试中记录限制。
- YOLO、OCR、二维码不再产生由框架取整导致的额外误差。
- Release x64 主工程构建通过。
- RegressionTests 全部通过。

## 实施顺序

1. `ToolResult` 浮点结果契约和 `ResultGeometry` 显式栅格转换。
2. `CoordinateTransform`、ROI、旋转 ROI 和结果 ROI 链路。
3. UI 绘制、结果导出和报告。
4. 模板匹配和直线检测。
5. Blob、轮廓和形状匹配。
6. 多点找色。
7. YOLO 两个后端。
8. OCR 和二维码。
9. 几何绘制适配、旧整数桥接删除和全量回归。

每一项都先补失败测试，再修改生产代码；当前批次构建和回归通过后才进入下一项。
