# 任务分组与执行说明

> 文档同步日期：2026-07-27。本文对应 `ToolChainState`、`ToolController`、`ToolsWindow`、`RunResultWindow` 和 `RecipeManager` 的当前实现；PLC 指定任务触发另见 [HARDWARE_INTEGRATION.md](HARDWARE_INTEGRATION.md)。

## 1. 任务分组

- 一个配方最多创建 16 个任务，默认名称依次为“任务01”“任务02”……。
- 任务支持重命名、上移、下移、启用、禁用和删除。
- 工具可以通过工具卡片的任务下拉框、任务工具窗口或拖放加入任务。
- 新增工具优先加入当前选中的任务；没有选中正式任务时进入“未分组”。
- 删除任务会同时删除该任务中的工具；删除前界面会进行确认。
- 任务顺序同时决定“全部执行”的顺序和结果总览卡片的顺序。
- 禁用任务仍保留在任务列表中，但不会执行、不会参与任务并行，也不会显示结果卡片。

“未分组”不是正式任务：只有存在未分组工具时才显示，并排在正式任务之后执行。

### 常用操作顺序

1. 在工具链顶部打开“任务列表”。
2. 点击“新建任务”，选中刚创建的任务。
3. 在任务设置中选择单图、文件夹或相机优先。
4. 添加工具；新工具会优先进入当前正式任务。
5. 也可以打开“工具分配”，通过“移入/移出”或拖放调整归属。
6. 使用任务上移/下移调整执行与结果卡片顺序。
7. 点击任务后，工具窗口会过滤到该任务，绑定图片存在时图像区同步显示任务预览图。

任务列表窗口支持停靠、浮动和纵向滚动，任务达到 16 个时仍可通过滚动访问后面的任务。关闭窗口只是隐藏界面，不会删除任务；可从工具链入口再次打开。

## 2. 每个任务的输入

每个正式任务可选择以下一种静态输入：

1. 单张图片；
2. 图片文件夹；
3. 不绑定任务图片，使用当前公共图片。

单张图片和图片文件夹互斥。重新选择单张图片会清除文件夹设置；选择文件夹会把文件夹第一张图片设为预览图。

图片文件夹使用递归扫描，支持 JPG、JPEG、PNG、BMP、TIF、TIFF 和 WebP，并按路径排序。执行规则如下：

- 第一次执行从第 1 张开始；
- 再次执行切换到下一张；
- 到达末尾后回到第 1 张；
- 同一轮中，一个任务内的全部工具始终共用同一张输入图；
- 单步执行不会在任务内部切图，完成一轮后再次从第一步开始时才切换；
- 循环执行每完成一轮切换一次。

每个任务分别保存自己的文件夹路径、当前位置和结果图，任务之间不会串图。

## 3. 工业相机优先

任务可勾选“使用工业相机（优先）”。该选项只选择输入优先级，不负责自动连接相机；相机仍需先在“设备连接”页完成连接。

工具链界面发起“执行全部 / 执行当前任务 / 循环”时，实际输入顺序为：

```text
已连接相机的新帧（任务勾选相机优先）
    ↓ 相机未连接或本次手动执行无法取得帧
任务绑定的图片文件夹或单张图片
    ↓ 任务未绑定图片
当前公共图片
```

当前所有任务共用设备页中已连接的同一台工业相机。一次“全部执行”只请求一张新帧，所有勾选相机优先的任务在该轮共用这张帧；任务内部的工具仍按顺序处理各自的图像链。

PLC Trigger 属于生产触发路径，规则更严格：只要相机在线就优先抓取新帧，不依赖任务的“相机优先”勾选；相机未连接时使用任务文件夹/单图，相机在线但本轮抓帧失败则发布 Error，不以旧图片掩盖相机故障。PLC Trigger 只执行绑定任务，且 Busy 或等待 ACK 时的新 Trigger 不排队。完整时序见 [硬件接入说明](HARDWARE_INTEGRATION.md#plc-触发指定任务拍照)。

相机地址为数字时表示设备索引，例如 `0`。Windows 通用 USB 相机优先尝试 `dshow`；`msmf` 和自动后端也可使用。日志出现 `OpenCV could not open camera source: 0` 时，先检查设备是否被浏览器、系统相机或其他程序占用。

## 4. 执行入口

| 入口 | 行为 |
| --- | --- |
| 执行全部 | 按任务列表顺序执行所有启用任务，最后执行未分组工具 |
| 执行当前任务 | 只执行当前选中的启用任务 |
| 全部单步 | 每次推进整条配方中的一个工具 |
| 当前任务单步 | 每次推进当前任务中的一个工具 |
| 循环 | 每轮完成后按设定等待时间继续执行，并推进任务文件夹图片 |
| 再次运行 | 保留上一次是“全部”还是“当前任务”的执行范围 |

工具卡片上的绿色边框和左侧强调线表示当前执行或最近一次单步对应的真实工具位置。

## 5. 任务并行

“任务并行”只作用于“执行全部”：

- 至少需要两个启用任务；
- 最多同时执行 4 个任务；
- 每个任务内部仍严格按工具顺序执行；
- 单任务执行、单步和循环保持顺序模式；
- 检测到跨任务结果 ROI 或 Fixture 依赖时自动回退到顺序执行；
- YOLO、OCR 等共享模型运行时会在必要区段串行化，避免共享会话并发冲突。

结果发布回到主线程完成，任务线程不会直接修改 ImGui 或公共图像状态。

## 6. 结果总览

- “执行全部”完成后默认打开任务结果总览。
- 卡片按启用任务的列表顺序排列，并显示状态、工具数量、耗时和任务结果图。
- 点击卡片进入任务详情；详情支持结果图查看、缩放、平移和最大化。
- 禁用任务和不存在的“未分组”不会生成空结果卡片。
- 标题栏“本轮总耗时”是整轮墙钟时间；任务卡片/工具行耗时用于观察任务内和单工具的执行成本。
- “执行当前任务”完成后保留当前任务结果；“执行全部”完成后按任务顺序刷新整轮卡片。
- 再次运行会复用当前结果窗口和纹理缓存，避免关闭旧窗口再创建新窗口造成闪烁。

## 7. 配方字段

任务数据保存在配方 JSON 的 `taskGroups` 中：

| 字段 | 含义 |
| --- | --- |
| `name` | 任务名称，也是工具 `groupName` 的关联键 |
| `enabled` | 任务是否参与执行和结果展示 |
| `imagePath` | 单图路径，或文件夹模式当前预览/执行图片 |
| `imageFolderPath` | 图片文件夹路径；为空表示单图模式 |
| `imageFolderIndex` | 文件夹当前图片索引，`-1` 表示尚未开始执行 |
| `imageFolderCount` | 最近一次扫描到的图片数量 |
| `cameraPreferred` | 是否优先使用已连接工业相机的新帧 |

旧配方缺少新增字段时会使用默认值，不影响原有工具和图片加载。

当前保存器写出 recipe version 4。任务通过名称与工具的 `groupName` 关联，因此重命名任务必须走 `ToolChainState::RenameTaskGroup()`，由 Core 同步更新工具归属；不要直接改字符串。

## 8. 状态边界

- `ToolChainState` 持有任务定义和工具归属，是任务配置的唯一事实源。
- `ToolController` 持有本轮执行范围、单步光标、任务结果图和耗时缓存。
- `ImageState` 持有主图窗口当前图；任务后台执行使用自己的图像快照，不直接覆盖其他任务。
- `RunResultWindow` 只查询执行结果并显示，不重新运行算法。
- 任务或工具移动、删除、加载配方后必须调用 `ToolController::OnToolChainChanged()` 清除索引相关缓存。
- “执行全部”的任务并发队列属于一次本地批次内部调度；PLC Trigger 使用独立的单槽握手状态，不是积压队列，两者不能混为一谈。
